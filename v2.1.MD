**Root cause found and fixed** — `engine/aite/exam.py::_normalize_ohlcv_frame`
compared lower-cased names only, so yfinance's capitalised `Date` column was
dropped together with the index. Every real vendor frame therefore arrived with
no timestamps and the provenance gate correctly-but-uselessly downgraded it to
`unverified`. The normaliser now:

* lower-cases after `reset_index` and maps `date/datetime/time/index` → `timestamps`,
* emits `bar_<n>` placeholders when there is genuinely no market time (so the gate
  can still see the difference), and
* coerces + sorts timestamps.

Reproduce with `python scripts/run_real_exam.py --json db/v21/real_exam.json`.

### 0.3 `tests/test_api.py` collects and passes — `live`

Rewritten for the authenticated API: 21 tests, all passing. It also surfaced two
real defects that are now fixed:

* `POST /api/v1/auth/logout` revoked only tokens in the request body, never the
  bearer that authenticated the call — logging out was a no-op. It now revokes the
  presented bearer plus any refresh token supplied.
* `POST /api/v1/auth/login` returned **500** for any unknown user because
  passlib 1.7.4 reads `bcrypt.__about__`, removed in bcrypt ≥ 4.1. `backend/auth.py`
  now calls bcrypt directly (same `$2b$` hashes, explicit 72-byte truncation) with
  a constant-cost dummy verify for missing users.

## 1. Panels + UI/UX — `partial`

**Shipped:** new `ZERO v2.1` tab with seven sub-tabs — *Suggestions, Trading, Desks,
Research, Agentic AI, Integrations, Forecast* — one card system, one palette, an
index selector pinned top-right of every tab, and lazy network calls (nothing runs
until a button is pressed). Shared CSS lives in `ui/v21_panel.py::_css`.

**⚡ Run all (next to the index selector):** one click runs *every* suggestion
engine for the selected index — GEX regime/flip, OLS hedge, pairs stat-arb, chart
pattern, and a full ecosystem cycle (breed → backtest → regime → arbitrage → risk
→ trade builder) — then renders one labelled consensus card on top
(`CONSENSUS LONG · 3 long / 0 short / 1 flat`, or `MIXED …` with no majority),
its action, confidence, per-engine votes table and invalidation. Results are
keyed by index + press nonce in session state, so they survive reruns, never leak
across a changed index, and a new press forces a fresh run. Consensus logic lives
in `engine/v21/signals.consensus` (unit-tested, not in the UI).

**Gap:** the legacy v1/v2 panels (`ui/components.py`, `ui/v11_components.py`,
`ui/kronos_panel.py`, `ui/aite/panel.py`, `ui/v2_panel.py`) still use their own
ad-hoc styles, so the terminal is visually mixed. Replacing them is a separate,
large migration; v2.1 did not silently rewrite them.

**Next:** move the legacy cards onto the `_card/_kv/_badge` kit, one panel at a
time, verifying each with `streamlit run app.py`.

## 4. Gamma exposure (GEX) — `live`

`engine/v21/gex.py`: Black–Scholes gamma per strike from the chain's own IV,
`GEX = OI_call·Γ_call − OI_put·Γ_put`, scaled by `spot²·0.01`; call wall (green) /
put wall (red), cumulative zero crossing = **gamma flip**, regime (+/−) with the
playbook text ("+ve: hedges sell rallies, buy dips, premium melts in a range";
"−ve: hedges chase, swings get faster and wider"), plus a labelled suggestion with
invalidation. Rendered as a green/red bar chart in Trading and as a card in
Suggestions.

Tests: ATM gamma > OTM gamma; fixture with call-heavy OI → `positive` regime;
empty payload → `available: False`.

## 13. 24/7 trading ecosystem — `live`

`engine/v21/ecosystem.py::run_cycle` runs the six stages — strategy creator →
backtester → regime detector → market arbitrage → risk management → trade builder
— on **real provenance-tagged bars**, logs every stage (including rejections),
writes a spec to `strategies/v21/<index>_<bot>.json` only when the backtest and
risk gate pass, appends to `db/v21/ecosystem.json`, publishes the suggestion to the
v2.0 alert bus and records a shadow day.

**24/7 is a running job, not a button.** `engine/v21/scheduler.py` owns the clock:
one daemon thread per process calls `run_cycle` for every index in
`ZERO_V21_CYCLE_INDEXES` (default NIFTY, BANKNIFTY, SENSEX) every
`ZERO_V21_CYCLE_SECONDS` (default 900 s, floor 60 s). It auto-starts when `app.py`
loads (`ZERO_V21_SCHEDULER=off` opts out) and also runs headless with
`python -m engine.v21.scheduler --loop`.

A loop meant to run for weeks has to stay bounded on disk:

| File | Cap |
|---|---|
| `db/v21/ecosystem.json` | newest 50 records (`ZERO_V21_LEDGER_LIMIT`), atomic temp+replace |
| `strategies/v21/` | newest 40 specs per index (`ZERO_V21_SPEC_LIMIT`) — genome ids are random, so without pruning every promoted cycle adds a file forever |
| `db/v21/scheduler.log` | 256 KiB, then `.1`/`.2`/`.3` (`ZERO_V21_LOG_MAX_BYTES`) |
| `db/v2/alerts.jsonl` | 2 MiB / 5000 rows (`ZERO_ALERT_MAX_BYTES`, `ZERO_ALERT_MAX_ROWS`) |
| `db/v2/shadow_{signals,scores}.jsonl` | 4 MiB / 20000 rows (`ZERO_SHADOW_MAX_BYTES`, `ZERO_SHADOW_MAX_ROWS`) |

The JSONL caps are a `stat` per append and a rewrite only when the byte cap is
crossed, so the cost is amortised over thousands of rows. `db/v21/scheduler.json`
is one fixed-key status object (runs, failures, consecutive failures, last
run/index/seconds/error/suggestion) — it cannot grow. Cycles run sequentially, so a
slow pass delays the next tick instead of stacking threads; a failure is logged,
counted and retried with exponential backoff capped at the interval, and never
kills the thread.
